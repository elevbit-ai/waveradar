Install & run

Windows (PowerShell):

irm https://elevbit-ai.github.io/waveradar/install.ps1 | iex

Linux / macOS:

curl -fsSL https://elevbit-ai.github.io/waveradar/install.sh | bash

Or with pip:

pip install "waveradar[esp32] @ git+https://github.com/elevbit-ai/waveradar.git"
# then:
waveradar                # radar from your router's signal
waveradar --source sim   # no-hardware demo
waveradar --source esp32 # true CSI via ESP32

The radar opens at http://127.0.0.1:8347. It calibrates for a few seconds, then walk around — you'll see it.

Sensing modes

--source auto

RSSI

Any router + the Wi-Fi already in your PC. Signal-strength sampling at ~6–9 Hz reveals motion presence, intensity and dominant Doppler frequency.

Hardware: none
--source esp32

CSI · ESP32

True Channel State Information: ~52 subcarriers with amplitude + phase at 50–100 Hz, streamed over USB. Richer micro-Doppler and multi-sector radar blips. Firmware included (Arduino IDE, 5 min).

Hardware: one $4 ESP32 board
--source sim

Simulator

Synthetic 52-subcarrier CSI with a scripted moving target — try the whole system with zero hardware. Used to render the demo video above.

Hardware: none

How it works

router ))) moving body ))) perturbed multipath ))) receiver
  → sliding window (64 samples), detrend static paths
  → Hann + FFT per channel, band-limited to 0.15–4 Hz
  → band energy vs adaptive quiet baseline → motion score
  → spectral peak → dominant Doppler (Hz)
  → per-subcarrier energy in 12 sectors → radar blips
  → canvas radar UI in the browser, ~12 Hz
  • Amplitude/phase variation — a moving reflector changes the path lengths the signal travels, modulating each subcarrier's amplitude and phase.
  • Doppler — motion at speed v shifts reflected energy by f_d ≈ 2v/λ (≈ 16 Hz per m/s at 2.4 GHz); human-scale motion concentrates in 0.15–4 Hz of channel variation, exactly the band WaveRadar isolates.
  • CSI — the per-subcarrier complex channel estimate every OFDM receiver already computes. The ESP32 exposes it; consumer routers usually don't, so RSSI mode is the zero-hardware path.
Honesty note: with a single radio link the radar detects that something moves, how much, and its Doppler content — not absolute position. Blip bearing is a stable projection of which multipath components are perturbed, not calibrated angle-of-arrival. True localisation needs multiple antennas or links. Use only on networks and spaces you own or administer, with the knowledge of the people present.
